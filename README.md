# Витрина цитатника

Сервис-прослойка между читателями и каталогом цитат.
Держит содержимое каталога в памяти и отдаёт читателям цитаты по одной.

## Запуск

```bash
docker build -t vitrina .
docker run --rm -p 8000:8000 --memory=256m --cpus=0.5 vitrina
```

Проверка:

```bash
curl http://localhost:8000/health
# {"status": "healthy"}
```

## Ручки

| Метод | Путь | Назначение |
|---|---|---|
| GET | /health | Проверка живости |
| POST | /catalog/source | Установить адрес каталога |
| POST | /import | Принять полный снимок каталога |
| PUT | /catalog/{quote_id} | Добавить/заменить цитату |
| DELETE | /catalog/{quote_id} | Снять с публикации |
| GET | /quotes/{quote_id} | Чтение цитаты |
| GET | /stats | Эксплуатационная сводка |

## Ключевые решения

- **Хранение.** Каждая запись хранится как готовый JSON-байт в `OrderedDict`.
  Это экономит память: 340 000 записей занимают ~100 МБ вместо 300+ МБ
  при хранении Python-объектов, и отдача читателю не требует повторной
  сериализации.
- **Парсинг снимка.** Формат гарантирован — снимок приходит по одной записи
  на строку. Парсим построчно через `iter_chunked`, без промежуточного
  списка из 340 000 `dict`. Пик памяти при импорте ≈ старый снимок + новый
  снимок ≈ 200 МБ, влезает в 256 МБ.
- **Защита каталога.** Три уровня:
  - семафор на 4 параллельных запроса — не разгоняем каталог;
  - single-flight — 100 читателей по одному id порождают один запрос;
  - глобальный экспоненциальный backoff при 503/сетевых ошибках,
    уважение заголовка `Retry-After`.
- **Атомарность снимка.** Подмена `store.data` одной ссылкой — читатели
  видят либо старый снимок, либо новый, без промежуточного состояния.
- **404 не кэшируется.** Редакция постоянно заводит новые цитаты; читатель
  по свежей ссылке обязан увидеть цитату сразу.
- **DELETE до снимка.** Снятые цитаты лежат в `store.removed` до следующего
  `/import` и не отдаются читателям, даже если ещё есть в каталоге.
- **PUT актуален сразу.** Запись кладётся в локальный кэш немедленно,
  без перечитывания из каталога.
